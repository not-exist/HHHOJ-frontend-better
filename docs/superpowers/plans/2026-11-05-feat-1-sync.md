# feat-1-sync：移除难度评级 + 对齐上游赞/踩 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 彻底删除本仓库自造的“按通过率估算六档难度”，并把上游 HHHOJ 现有的赞/踩（`zan`）UI 以 TwilightOJ 的视觉语言补到题目、比赛、博客与评论上。

**Architecture:** 先做互不兼容的清理（难度）与纯逻辑（投票状态机），再改接口映射与共享类型，然后新增一个自包含的 `Zan` 组件，最后在互不重叠的页面文件上并行接入。所有赞/踩行为以 HHHOJ 服务端语义为准：同侧再点不变、另一侧归零；开启多票时每次 ±1，普通用户上限 ±20，界面显示 `×N`。

**Tech Stack:** React 18、TypeScript 5.6（strict）、Vite 5、react-router-dom 6、i18next、lucide-react、Node 22 内置 `node:test`（仅用于纯函数测试）。

**Spec:** 会话需求（2026-11-05）与上游源码证据：`/home/qzez/HHHOJ/server/src/site/zan.cpp`、`server/include/site/zan_vote.hpp`、`frontend/src/components/Zan.tsx`、`frontend/src/styles/uoj-theme.css`。本文件第 1 节为设计说明。

- 投票语义必须与上游一致：非多票目标同侧点击返回原值（不取消），对侧点击归零；多票目标累加，普通用户上限 ±20，超限报错。

## Review Focus

1. **非多票同侧点击**：已赞状态下再点赞必须保持 `+1`，不能像现有讨论页那样取消成 0。
2. **连续快速点击**：请求未返回时按钮禁用，避免双倍计数或旧响应覆盖新状态。
3. **比赛内题目**：带 `?contest_id` 打开的题目，投票请求必须带 `contest_id` 查询参数，否则服务端拒绝。
4. **可点击容器内的按钮**：题库表格行、比赛卡片、讨论列表项的整行点击不能因点“赞/踩”而跳转。
5. **多票上限**：普通用户在第 20 次再点应收到错误 toast 且界面保持原值；管理员不受限。

## 1. 设计说明

### 1.1 难度删除范围

难度是本仓库的估算产物，HHHOJ 没有该字段。删除后：

- 题库不再有“难度”筛选器、难度列；
- 题目详情、个人主页已通过列表不再显示难度徽章；
- 领域类型、mock 数据、i18n、CSS 变量与文档中的难度说明一并删除，避免死代码。

### 1.2 赞/踩数据流

上游读取接口已带字段（本地源码证据）：

| 接口 | 字段 |
|---|---|
| `GET /api/problems` | 每项 `zan`、`my_zan`、`zan_multi` |
| `GET /api/problems/:id` | `problem.zan`、`problem.my_zan`、`problem.zan_multi` |
| `GET /api/contests` | 每项 `zan`、`my_zan`、`zan_multi` |
| `GET /api/contests/:id` | 同上 |
| `GET /api/blogs/:id` | `blog.zan`、`my_zan` |
| 评论 | 每条 `zan`、`my_zan` |
| `GET /api/blogs` | 只有 `zan`，**没有 `my_zan`** |

写接口：`POST /api/zan`（比赛内题目为 `POST /api/zan?contest_id=N`），body `{ type: "P"|"C"|"B"|"BC", id, delta: 1|-1 }`，返回 `{ zan, my_zan }`。

### 1.3 UI 形态

一个 `Zan` 组件：`ThumbsUp` / `ThumbsDown` 两个图标按钮 + 净票数（正数带 `+`，负数带 `-`）。已赞按钮绿色（`--v-acced`），已踩红色（`--v-wrong`），计数同色；多票目标在计数后显示 `×绝对票数`，整组 `title` 提示“可重复点击，普通用户最多 20 次”。

### 1.4 放置位置（对齐上游）

| 页面 | 目标类型 | 数据来源 |
|---|---|---|
| 题库 `/problems` | `P` | 列表项 `zan/my_zan/zan_multi` |
| 题目详情 `/problem/:id` | `P` | 详情 `problem.*`，有比赛上下文时带 `contestId` |
| 比赛列表 `/contests` | `C` | 列表项 `zan/my_zan/zan_multi` |
| 比赛详情 `/contest/:id` | `C` | 详情 `contest.*` |
| 讨论列表 `/blogs` | `B` | 列表 `zan`；无 `my_zan`，初始按 0 处理 |
| 帖子详情 `/blogs/:id` | `B` | 详情 `zan/my_zan` |
| 顶层评论 | `BC` | 评论 `zan/my_zan` |

不分页、不改服务端；回复（reply）与个人主页帖子列表保持现状，不新增赞/踩。

### 1.5 已知限制

博客列表接口不返回 `my_zan`，因此列表里的按钮在首次点击前无法高亮“我是否已赞”；点击后以服务端返回的 `my_zan` 为准。README 与验证文档如实记录。
